# Linx WordFinder: plan and decisions

A third LetterLinx game: a daily word hunt. Everyone gets the same static board each day (per language),
hiding 6 words on one topic. Built on the `wordfinder` branch in the phases below; each phase ends with
tests passing, a commit, and a check-in.

## Agreed decisions

| Decision | Choice |
|---|---|
| Grid | 6 × 10, same as the other games (turned on its side on wide screens) |
| Words | 6 per puzzle, single words, 3–10 letters, 45 letters total at most |
| Spanish | Ñ allowed; accents stripped for matching (PERÚ matches PERU), shown in lists |
| Hint penalty | +30 seconds per hint, shown in the results |
| Leaderboard identity | Signed-in players, or guests with a nickname that doesn't match a member's screen name |
| Attempts | One ranked attempt per puzzle per language (per account, or per device for guests); no replays |
| Archive | Not included for now |
| AI generation | Claude API (Claude Opus 5.5), key kept on the server (`ANTHROPIC_API_KEY`) |

## Where it fits

- Games tab: a third card, "Linx WordFinder". The Play tab shows whichever game is selected.
- Leaderboard tab: a third tab, "WordFinder", with the calendar for past days.
- `/wordfinder` and `/es/wordfinder` open the game directly (used by the share link).
- Admin: a "WordFinder puzzles" section in the existing admin dashboard.

## Reused from LetterLinx

Tile grid and styling (including the sideways tablet layout), drag-to-select with 8-direction adjacency and
the trail line, the sound engine (with the iPhone fixes), GO screen title card, results screen, share box,
English/Spanish text system and `/es/` page, accounts, sessions and admin access, leaderboard tabs and the
past-days calendar, Vercel API functions and the Neon Postgres database, and the page generator for
titles and link previews.

## Phases

1. Codebase review and plan (done).
2. Puzzle rules and board generator: pure functions in `wordfinder.js`, tests in `test/`.
3. Gameplay, single player and local, with a few hard-coded sample puzzles.
4. Backend and leaderboard: storage, server-side checking and timing, leaderboard, streaks and stats.
5. Sharing: share text, Web Share API and clipboard, link previews.
6. Admin area: calendar, review and edit, board preview and shuffle, approve and reject, backup pool, alerts.
7. AI month generation.
8. Polish: Spanish text, accessibility, reduced motion, animation timing, end-to-end tests.

## How the server side works (phase 4)

- `api/wordfinder.js` is the only endpoint; `api/_wf.js` holds the logic. Tables `wf_puzzles` and `wf_plays` are
  created automatically on first use, like the other tables.
- Puzzle for a day: the approved puzzle for that language and date; otherwise the oldest puzzle in the backup pool
  takes the day; otherwise one of the built-in samples (`api/_wf_samples.js`, never served to browsers).
- The board is sent only after GO; the words only once all six are found. Each drag is checked on the server and
  timed by the database clock. A day more than one away from the server's UTC date is refused.
- One attempt per language per day: per account when signed in, per device (a random `llx_wfg` cookie) otherwise.
  A game started as a guest becomes the player's if they sign in that day.
- Leaderboard: fastest total time (hints included), ties to whoever finished first. Confirmed members, or guests
  who add a nickname. Nicknames: 2–20 letters or numbers, not a member's screen name, not on the blocklist.
  Solves under 5 seconds are kept but never ranked.
- Stats (played, best time, current and max streak) come from the same table, per account or per device.

## Sharing (phase 5)

- End screen Share button: the phone's share sheet where there is one, otherwise the text is copied
  (with an older copy method for browsers without the clipboard API). The text has the puzzle number, topic, time
  and hints used, never the words, e.g. "Linx WordFinder #142 · Countries / ⏱ 2:47 (1 hint) / …/wordfinder".
- `/wordfinder` and `/es/wordfinder` (redirected to the slashed address) open straight into WordFinder. They are
  generated by `build-pages.js` with their own title, description, canonical address and preview image
  (`og-wordfinder.png`, `og-wordfinder-es.png`), and are listed in `sitemap.xml`.

## Admin (phase 6)

- In the existing admin dashboard (Settings → Admin dashboard), section "Linx WordFinder puzzles". The tools are in
  `wf-admin.js`, downloaded only when an admin opens the dashboard; the API is `api/wf-admin.js` (admins only).
- Alerts for the next 7 days (UTC): days without an approved puzzle in a language, and whether the backup pool or a
  built-in sample will fill them.
- Month calendar: each day shows its English and Spanish puzzle (approved, draft, missing, or filled automatically).
- Editor: English and Spanish side by side (stacked on phones), live rule checks, board preview with numbered,
  coloured words, Shuffle (new seed). The server rebuilds the same board from the seed when saving.
- Statuses: draft → approved (live on its day). Editing an approved puzzle takes it back to draft. Approved puzzles
  lock once their day may have started anywhere (UTC date + 1) or once anyone has played them.
- Swap two days (both languages, neither started), move to the backup pool, reject, assign a backup to a day,
  and create puzzles by hand for a day or for the pool.

## Writing puzzles with Claude (phase 7)

- Server only: `api/_wf_ai.js` (the content guidelines are the `GUIDE` text there) and the `ai_*` actions in
  `api/wf-admin.js`. The key (`ANTHROPIC_API_KEY`) stays in Vercel; without it the buttons are off with a note.
- Model: Claude Opus 5.5 (`WF_AI_MODEL` can override it), structured JSON output, effort "medium", and
  Anthropic's server-side fallback so a mistaken refusal is retried on another model.
- "Write <month> with Claude": one request plans a topic for every empty day from today on (avoiding topics from
  the last 90 days, the coming months and the backup pool; easier early in the week, harder at weekends), then one
  request per day writes English and Spanish. Each result is checked against the rules and must make a board; a
  day that breaks a rule gets one more try with the problems listed, then is saved as "needs fixing" (no board,
  can't be approved). Everything is saved as drafts with source "ai"; nothing goes live until approved.
- In the editor: "Write with Claude" fills both languages (not saved until you save), and each word has
  "↻ word" (a different word and hint) and "↻ hint" (a new hint for the same word).
- Each request is one short call so it finishes inside Vercel's 60-second limit; the browser runs the month day
  by day and can be stopped. Rough cost: about 10 cents a day, $3–4 a month.
- Tests use a local stand-in for the Claude API (`test/wordfinder-ai.test.js`), so no key or network is needed.
